# Review & Feedback Specification Template

## Overview

This template defines how outcomes are analyzed, lessons are extracted, and improvements are fed back into the operation.

## Structure

### Review Cadences

- **Review Type**: What's being reviewed? (execution, strategy, outcomes)
- **Frequency**: When does this review happen? (after each action, daily, weekly, etc.)
- **Trigger Conditions**: What other events might trigger a review?
- **Review Owner**: Who is responsible for this review?

### Analysis Frameworks

- **Analysis Name**: What are we analyzing?
- **Questions to Answer**: What specific things should we look at?
- **Data Inputs**: What data sources go into this analysis?
- **Success Indicators**: What indicates a good outcome?
- **Failure Indicators**: What indicates a bad outcome?

### Feedback Mechanisms

- **Insight Type**: What kind of learning are we extracting? (pattern, outlier, optimization, warning)
- **Feedback Loop**: How does this insight get back into the system?
  - Does it refine Strategic Spec?
  - Does it adjust Execution Spec?
  - Does it change Observability Spec?
- **Implementation Timeline**: When does feedback get acted on?

### Reporting & Communication

- **Report Type**: What gets reported?
- **Report Audience**: Who needs to see it?
- **Report Frequency**: How often is it generated?
- **Report Format**: What format? (summary, detailed, visual, narrative)

### Optimization Priorities

- **Priority**: What should be improved first?
- **Effort vs. Impact**: Is this easy to change? How much would it help?
- **Dependencies**: Does this improvement depend on other changes?

## Usage

Review Agents will read this spec to determine:
- "When should a review happen?"
- "What specific analysis should I run?"
- "What feedback should loop back to the system?"

Be specific about review triggers, analysis questions, and feedback mechanisms.
